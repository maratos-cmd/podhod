# Сигналы отдыха: AlarmKit и выбор звука

> Историческое описание версии от 25 октября. **4 ноября полноэкранный AlarmKit отключён по обратной связи пользователя.** Актуальное поведение: [короткие уведомления и исправление сохранения](ИСПРАВЛЕНИЕ_ОТДЫХА_2026-11-04.md).

25 октября 2026. Исходное [ТЗ P0](P0_REST_ALERTS_SPEC_2026-10-25.md). Это рабочая сборка; установка на физические iPhone и отправка в GitHub в рамках P0 не выполнялись.

## Как пользоваться

1. Открой **Профиль → Настройки → Уведомления**. «Громкие сигналы отдыха» включены по умолчанию. Разрешение на будильники запрашивается при первом отдыхе, включении режима или запуске проверки.
2. В **Звук окончания отдыха** выбери системный сигнал либо один из шести собственных: короткий, двойной, тройной, электронный, громкий звонок, будильник. ▶ прослушивает файл; повторное нажатие останавливает. Уход с экрана или в фон прекращает прослушивание. Выбор сохраняется и применяется к ещё идущему отдыху.
3. Вернись назад и нажми **Проверить сигнал через 10 секунд**. После выдачи разрешения дождись подтверждения постановки, заблокируй iPhone. Это настоящий системный сигнал, с отдельным названием и кнопкой отмены в приложении. Во время текущего отдыха проверка недоступна.
4. Сработавший будильник останови системной кнопкой. Повтора и snooze нет; остановка не отмечает подход и не запускает новый отдых. Пропуск отдыха, завершение и отмена тренировки также снимают её сигнал.

Публичный API не даёт произвольно выбирать или немедленно прослушивать всю библиотеку системных рингтонов. Поэтому «Системный» использует настоящий `.default`, а его прослушивание выполняется через проверочный будильник. Другие варианты — собственные синтезированные файлы приложения, не копии системных мелодий. «Без звука» сохранён для совместимости и использует обычное уведомление. Импорт файла из «Файлов» оставлен отдельным необязательным улучшением.

## Что реализовано

- iOS 26+: `AlarmManager`, контекстное разрешение, `NSAlarmKitUsageDescription`, системный одноразовый сигнал на `RestTimer.endsAt`. AlarmKit поддерживает заметное системное представление и звук при Silent/Focus; реальные условия на телефоне требуют проверки.
- Один отдых — один UUID и один канал доставки. Изменение времени/звука/следующего действия безопасно заменяет сигнал; быстрые изменения сериализованы. Поздний результат устаревшего запроса очищается. Ошибка удаления препятствует созданию второго канала.
- Перезапуск сверяет сохранённый журнал с системными сигналами, сохраняет действующий и удаляет посторонние старые сигналы приложения. Истёкший или закрытый отдых не ставится заново. Короткий переход в состояние звонка не обрывается при возврате в приложение.
- Если AlarmKit не смог назначить сигнал, сначала проверяется и очищается возможное частичное назначение, затем используется разрешённое обычное уведомление. Успешный резервный канал сохраняется для того же отдыха после системных обновлений и перезапуска; новое время или следующий отдых снова допускает AlarmKit.
- iOS 17–25, отказ разрешения или выключенный громкий режим: UserNotifications, выбранный звук, баннер/звук в открытом приложении. Уведомления о перерыве в тренировках имеют независимый ID и не удаляются.
- Общая логика следующего действия для AlarmKit, уведомления, экрана тренировки и Live Activity: следующий незавершённый подход, другое упражнение либо «Все подходы выполнены / Можно завершать тренировку», включая суперсеты.
- Необязательные новые настройки и метаданные включены в JSON-копии. Схема остаётся 2, старые копии читаются. История, программы, измерения и текущая тренировка не сбрасываются.
- Существующая Live Activity остаётся единственным отсчётом отдыха: AlarmKit использует фиксированную дату без отдельного countdown и без дополнительного расширения.

## Ограничения системы

Громкость контролирует iPhone: приложение не выставляет 100%. Проверь «Настройки → Звуки, тактильные сигналы → Рингтон и уведомления» и отдельно выполни проверочный сигнал. Громкость preview внутри приложения может отличаться от системного будильника. Освещение экрана, вывод звука через подключённые устройства и режим энергосбережения требуют проверки в конкретных условиях.

Обычные уведомления не гарантируют обход Silent Mode или Focus. В текущем SDK опция запроса `.timeSensitive` помечена устаревшей в пользу entitlement. Подпись и entitlements сохранены; уровень `.timeSensitive` устанавливается только если система действительно сообщает разрешённый `timeSensitiveSetting`. Critical Alerts, приватные звуковые ID, изменение общей громкости, постоянное фоновое аудио и имитация пробуждения экрана не используются.

Системный будильник может ждать ручной остановки. Публичное API не предоставляет здесь собственного гарантированного фонового автоотключения через N секунд. При следующем согласовании приложение удаляет звонящие сигналы старше 5 минут и просроченные ожидающие/доставленные сигналы старше 30 секунд. Это очистка при событии/открытии приложения, не фоновый секундомер.

## Проверки на физическом iPhone — ещё не выполнены

Для каждого режима сначала запусти короткую проверку, затем проверь настоящий отдых после подхода. Избегай проверки во время реального подхода с весом.

- [ ] Звук и заметный системный экран при заблокированном iPhone; включение дисплея, если iOS разрешает.
- [ ] Silent Mode, Focus / «Не беспокоить», режим энергосбережения.
- [ ] Приложение в фоне, приостановлено и закрыто; сигнал не требует его повторного открытия.
- [ ] Системный звук и каждый выбранный файл; preview и настоящая громкость отдельно.
- [ ] Проверочный сигнал: запуск после разрешения, срабатывание через 10 секунд, отмена и остановка.
- [ ] Укорочение/продление отдыха, быстрая смена галочек, изменение звука — один актуальный сигнал.
- [ ] Пропуск, снятие галочки, завершение и отмена тренировки убирают ожидающий и звонящий сигнал.
- [ ] Перезапуск в середине отдыха сохраняет сигнал; перезапуск после остановки не повторяет его.
- [ ] Отказ и отзыв разрешения; резервное уведомление; оба разрешения выключены.
- [ ] Следующий подход, другое упражнение, последний подход всей тренировки и суперсет.
- [ ] Одна карточка отсчёта в Live Activity / Dynamic Island, без дублирующего countdown AlarmKit.

Автоматические результаты и сборки записаны в [VALIDATION.md](../VALIDATION.md). Симулятор не подтверждает акустическое поведение, Silent/Focus или включение физического дисплея.

## Основания API

Реализация сверена с установленным SDK iOS 26.5 (Xcode 26.6) и официальными материалами Apple: [постановка будильника AlarmKit](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit), [Meet AlarmKit, WWDC25](https://developer.apple.com/videos/play/wwdc2025/230/), [AlertSound](https://developer.apple.com/documentation/activitykit/alertconfiguration/alertsound). В бинарном файле AlarmKit подключён через `LC_LOAD_WEAK_DYLIB`, минимальная версия остаётся iOS 17.0. Существующие Bundle Identifier, Team и восемь конфигураций сборки сохранены.
